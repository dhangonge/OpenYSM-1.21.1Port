## 说明

本仓库包含了 YesSteveModel (YSM) 2.6.5（2026年4月）版本的完整源代码。

包含1.21.1 NeoForge版本的全部源码。

**请注意：项目并非 Production Ready，可能存在命名语义错误，渲染错误等问题，如果您在使用过程中遇到了任何问题请打开 Issue 反馈，最好附带截图和可能的报错日志。**

## 已知缺陷（Known Issues）

本移植版在 1.21.1 NeoForge 上已完成核心功能对齐（模型渲染、女仆兼容、GUI、服装切换），但仍有以下已知缺陷/限制，使用前请知悉：

- **女仆渲染动画表达式未完全初始化**：女仆（Touhou Little Maid）的 `animationMap` 在装配时未走 `initAnimationControllers`，已做 null 防空避免渲染崩溃，但女仆的部分初始化动画表达式（如眨眼）可能不执行
- **classic 轮盘（旧 UI）分页逻辑异常**：部分模型在 classic 轮盘下选项可能为空（modern 轮盘正常）；另 classic 轮盘按钮开关状态由自绘标记显示，与原版纹理风格不同
- **Android（MobileGlues）GPU 渲染路径不可用**：`GpuRenderPath` 与 MobileGlues 翻译层不兼容（官方 YSM 的 GPU 栈同样需要额外适配），默认使用兼容渲染路径
- **全屏背景模糊通过 Mixin 按类名禁用**：为避免 YSM 界面在 1.21.1 原版背景模糊下被二次模糊，`ScreenBlurDisableMixin` 会按 `com.elfmcys.yesstevemodel` / `rip.ysm` 类名取消模糊，属行为对齐方案而非原版还原
- **模型加载为单线程**：上游使用 ForkJoinPool + 懒加载并发解析，本移植版暂为单线程，模型较多时加载耗时略长
- **低版本二进制/未加密模型兼容性未充分测试**：格式 < 15 的旧模型未完整验证
- **服装/变体机制依赖模型命名约定**：同名动画（如不同动画文件中的 `parallel0`）合并时按文件顺序覆盖，模型作者需遵循 YSM 命名规范（详见 `YSMBinaryDeserializer` 中 arrow 动画的归位处理）

如果遇到问题请打开 Issue，最好附带截图和日志（`logs/latest.log`）。

## 开发方式：Vibe Coding

本项目由**人类作者 + AI 编程代理**协作开发（vibe coding 模式）：

- 作者用自然语言描述需求/反馈（如“丰川祥子服装叠加”“日志在 debugXX”），AI 代理负责读代码、定位根因、实现修复、构建 jar、推送仓库
- 调试流程以**真实设备运行日志**为准：通过临时诊断日志（游戏内 `[YSM-*]` 标记）采集运行时证据，定位后移除诊断代码再交付
- 代码审查依赖：字节码对比上游 jar（`javap`）、离线解密模型文件验证机制、多轮设备实测
- 因此代码风格/命名可能存在 AI 生成痕迹，欢迎 PR 优化；提交历史中的 commit message 多为修复摘要

## 为什么开源？

我们决定将新版 YSM 源码开源，主要基于以下几个原因：

### 1. 新版本的完全重置

新版 YSM 已经经过完全重新设计和开发，采用了全新的架构和加密方式。

我们认为这个全新的架构和加密方式很酷，因此发布了源代码供大家学习研究和使用。

### 2. 新版加密的现状

此前社区已经出现了一个破解 YSM 2.6.5 及以下版本加密的工具和方法，新版的加密机制实际上已经失去了保护作用。

同时，目前社区中的大部分新模型都已经公布了源文件或者被解密，新版加密已经毫无实际意义。

### 3. 支持开放的游戏氛围

我们注意到社区中没有开发者制作了去除加密功能的最新 YSM 版本，这表明了这是一个蓝海市场。

OpenYSM 开发组一直非常支持开放、自由的游戏开发氛围，我们希望通过开源新版源码，为其他开发者的二次开发和学习提供便利。

## 修改

我们相比已经发布的 YSM 版本做出了以下修改

- 使用 Java 重写了加载和渲染逻辑，现在可以脱离 Native 运行，例如在 MacOS，RISC-V 甚至手机上
- 支持现有的已加密的 YSM 模型
- 添加了`/openysm cache dump`命令帮助你调试模型传输，导出服务器中的所有模型
